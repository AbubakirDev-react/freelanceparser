# Order Radar

Личный инструмент фрилансера: собирает новые заказы с нескольких площадок
(fl.ru, kwork.ru, profi.ru, Яндекс Услуги) в одно место и шлёт их в Telegram.

Владелец — начинающий фронтенд-разработчик (React + TS, немного Supabase).
Общение по-русски, коротко. К каждому решению давать 1–2 предложения «почему».

## Стек
- Node + TypeScript (strict), код в `src/`
- Supabase (Postgres): таблицы `orders` (UNIQUE(source, external_id)) и `settings`
- Telegram-бот на grammY
- Тесты: vitest на сохранённых HTML/RSS-фикстурах
- Расписание: GitHub Actions cron (5–10 минут), секреты в GitHub Secrets
- Бонус: React + Vite страница, Supabase RLS, anon-ключ только на чтение

## Ключевые типы
```ts
type Order = { source; externalId; title; description; budget; url; publishedAt };
interface OrderSource { name: string; fetchNew(): Promise<Order[]> }
```

## Жёсткие правила (не нарушать)
1. НЕ заходить в аккаунты владельца скриптами, НЕ хранить логины/пароли площадок,
   НЕ обходить капчу и антибот-защиту.
2. Брать только то, что площадка отдаёт открыто (публичные страницы, RSS)
   или присылает сама (email/Telegram-уведомления).
3. Вежливый парсинг: не чаще раза в 5 минут на источник, понятный User-Agent,
   соблюдать robots.txt. Если сайт блокирует — остановиться и сообщить, обходы не искать.
4. Секреты (токены, ключи Supabase) только в `.env`, который в `.gitignore`.
   Никогда не коммитить и не печатать их.
5. Если источник нельзя взять легально — честно сказать и пропустить.

## Как работать
- Вертикальными срезами: один источник end-to-end, потом следующий.
- После каждого этапа: запустить, показать реальный вывод, git commit на русском.
  Не говорить «готово» без проверки запуском.
- Больше 2 неудачных попыток — остановиться и рассказать, что пробовал.
- Без лишних библиотек и абстракций: простота важнее красоты.
- Миграции Supabase применять только после подтверждения владельца.
- В конце — README: запуск, переменные `.env`, что работает, что нет.
