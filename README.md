# Order Radar

Личный радар заказов для фрилансера. Каждые 10 минут собирает новые заказы с **kwork.ru** и **fl.ru**,
складывает их в Supabase без дублей и присылает в Telegram те, что прошли фильтр.

```
GitHub Actions (cron */10)
  └─ npm start
       1. команды бота (/keywords, /minbudget) → таблица settings
       2. kwork.ru/projects, fl.ru/projects → таблица orders (UNIQUE source+external_id)
       3. заказы с notified_at = null → фильтр → Telegram → notified_at = now()
```

## Что работает

| Что | Статус |
|---|---|
| kwork.ru: 12 свежих заказов с 1-й страницы (JSON из `window.stateData`) | ✅ |
| fl.ru: 30 свежих заказов (HTML `/projects/`, RSS запрещён в robots.txt) | ✅ |
| Дедупликация через `UNIQUE(source, external_id)` в базе | ✅ |
| Telegram: заголовок, бюджет, описание, кнопка «Открыть заказ» | ✅ |
| Фильтр по ключевым словам и минимальному бюджету, команды бота | ✅ |
| Запуск каждые 10 минут в GitHub Actions | ✅ |
| Тесты парсеров на сохранённых страницах (vitest) | ✅ |

## Ограничения (честно)

- **profi.ru и Яндекс Исполнители не подключены.** Заказы видны только после входа в аккаунт, а входить скриптом
  мы не будем (правила площадок, риск бана). Возможный путь на будущее: пересылка email-уведомлений.
- **Бот отвечает на команды с задержкой до 10 минут**: скрипт запускается по расписанию и не висит постоянно.
- **На kwork видна только 1-я страница** (12 заказов): `?page=` запрещён в robots.txt. При опросе раз в 10 минут
  этого хватает, но в часы пик что-то можно пропустить.
- **Время заказов fl.ru приблизительное**: сайт показывает только «2 часа 31 минуту назад».
- **Вакансии fl.ru тоже приходят**: они идут в той же ленте, что и заказы. Отсеять их можно ключевыми словами.
- Если площадка поменяет вёрстку, парсер упадёт с понятной ошибкой, а запуск в Actions станет красным
  (GitHub пришлёт письмо).

## Правила, которые соблюдает скрипт

Только публичные страницы, без логинов и без обхода капчи. Не чаще раза в 5 минут на источник,
честный User-Agent, robots.txt соблюдается. На 403/429 источник останавливается, обходы не ищем.
Подробно в [CLAUDE.md](CLAUDE.md).

## Запуск локально

Нужен Node 24+.

```bash
npm install
cp .env.example .env   # и заполнить, см. ниже
npm test               # тесты парсеров, сеть не нужна
npm start              # один полный прогон
```

> `npm start` ходит на площадки по-настоящему. Если уже работает cron в GitHub Actions, лучше запускать
> вручную через **Actions → Order Radar → Run workflow**, чтобы не делать лишних запросов.

### Переменные `.env`

| Переменная | Где взять | Где нужна |
|---|---|---|
| `SUPABASE_URL` | Supabase → Project Settings → API | скрипт |
| `SUPABASE_SECRET_KEY` | Supabase → Project Settings → API Keys → Secret keys (`sb_secret_...`) | скрипт. **Обходит RLS, только для сервера** |
| `TELEGRAM_BOT_TOKEN` | @BotFather → `/newbot` | скрипт |
| `TELEGRAM_CHAT_ID` | напиши боту, потом `getUpdates` (поле `message.chat.id`) | скрипт |
| `VITE_SUPABASE_URL` | то же, что `SUPABASE_URL` | веб-страница |
| `VITE_SUPABASE_PUBLISHABLE_KEY` | Supabase → API Keys → Publishable key | веб-страница (попадает в браузер) |

`.env` лежит в `.gitignore`. Для GitHub Actions те же 4 серверные переменные задаются в
**Settings → Secrets and variables → Actions**.

### База

Схема лежит в [supabase/migrations](supabase/migrations). Применить можно в Supabase → SQL Editor, файлы по порядку.

## Команды бота

| Команда | Что делает |
|---|---|
| `/keywords react, сайт, бот` | присылать только заказы, где есть хотя бы одно слово (поиск подстрокой, без учёта регистра) |
| `/keywords -` | присылать всё |
| `/keywords` | показать текущие слова |
| `/minbudget 5000` | не присылать дешевле 5000 ₽. Договорные приходят всегда. `0` = без ограничения |
| `/help` | справка и текущие настройки |

Команды принимаются только из чата `TELEGRAM_CHAT_ID`.

## Структура

```
src/
  main.ts            точка входа: команды → сбор → рассылка
  types.ts           Order и OrderSource: общий формат для всех площадок
  sources/kwork.ts   парсер kwork (+ kwork.test.ts, __fixtures__/)
  sources/fl.ts      парсер fl.ru (+ fl.test.ts)
  filter.ts          фильтр по словам и бюджету
  commands.ts        разбор команд бота (чистая функция)
  db.ts              Supabase: orders и settings
  telegram.ts        отправка сообщений и приём команд (grammY)
  http.ts            fetch с User-Agent и остановкой на блокировке
.github/workflows/radar.yml   cron каждые 10 минут
```

Новая площадка добавляется так: файл в `src/sources/`, который реализует `OrderSource`, плюс одна строка в `main.ts`.
